Four projects in one solution. One host process runs the Discord bot, the web UI, the REST API and the SignalR hub together.

Line counts exclude obj/, bin/ and the generated Migrations/ folders. The test project is almost as large as the host project.

The host project carries most of the weight. DiscordBot.Bot holds 11 Discord event handlers, 31 command-module files, 101 service files, 30 controllers, 69 Razor Pages and a 4-file Blazor foundation. Service registration is split across 27 extension files in src/DiscordBot.Bot/Extensions/, one per domain.

The web UI is Razor Pages with a Blazor Server island foundation. The Graphite design system (merged 2 September) restyles every page through CSS custom properties in site.css and a Tailwind config that reads them. Phase 0 of the Blazor plan (merged 24 June) added MapBlazorHub(), two interop services and two shared components. The only live island is a probe on /Components.

Observability is built in. Serilog with Elastic, Loki and Seq sinks; OpenTelemetry traces, metrics and a Prometheus exporter; Elastic APM. Two health checks (database, Discord gateway) answer at /health with version and timestamp.

Coverage is deep on services and thin on commands. 14 test attributes cover 31 command-module files. docs/TEST_COVERAGE_GAPS.md, written on 1 April, says the same: one of 31 modules tested, three of 11 handlers tested. It lists a minimum case set per module. Nothing in the test folder has changed that picture since. The suite grew by 19 attributes in five months.

CI on main is green, and has been since 1 April. The last four main runs (663, 676, 688 and 703) all passed. Runs 657, 659, 660 and 662 failed on 1 April during the v1.5.0 release; each was a flaky timing test, and the fixes landed the same day. The CI job builds, runs tests with Cobertura coverage, and uploads results. No coverage threshold is enforced.

Risk

The flaky-test fixes of April were the last test work. Six commits in April rewrote timing-dependent tests in ConnectionStateService, PerformanceMetricsBroadcast, AuditLogQueueProcessor and MemberSyncQueue. The xUnit1031 warnings still in the build log are the same pattern, unfixed. The next slow CI runner will find them.
